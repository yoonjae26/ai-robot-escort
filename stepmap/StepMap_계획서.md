# StepMap 구현 계획서 (v2: 디자인 단계)

> 사족보행 로봇(Unitree Go2 EDU)으로 보도의 단차·균열·흔들리는 블럭을 측정하고, 그 결과를 지도로 보여주는 CLI 도구

- 작성일: 2026-10-18
- 팀: 홍윤재(3학년, AI기술학과, 개발), 1학년 팀원(실험·데이터·발표)
- 환경: Unitree Go2 EDU, ROS 2 Humble, 뎁스 카메라(외부 장착) + 내장 카메라, Python
- **현재 단계: 디자인. 예시 데이터로 데이터 형식·지도·대시보드를 먼저 완성하고, 실측 데이터가 나오면 같은 형식으로 교체한다.**

---

## 1. 한 줄 요약

로봇개가 보도를 걸으며 **카메라로 보고(단차·균열), 발로 눌러 확인(흔들리는 블럭)**한 결과를 하나의 형식으로 모아, **위치별 문제 지점 지도**를 만든다.

## 2. 배경과 위치 설정

- 서울동행맵은 휠체어 이용자에게 2cm 이상 단차, 1/8 이상 경사, 1.2m 이하 보도폭을 피하는 경로를 안내한다. 그러나 데이터는 **지하철역 반경 300m를 사람이 현장조사**한 약 3,500개 지점이고, 시민 제보는 **사진 + 위치 + 유형**만 받아 현장 재확인이 필요하다.
- 해외(미국 Daxbot 등)는 바퀴형 로봇으로 보도를 정밀 측정하지만 **표면 모양만** 재고 계단·턱을 넘지 못한다.
- 시애틀 AccessMap 팀도 균열, 울퉁불퉁한 표면, 횡단 경사 데이터가 없다는 한계를 밝혔다.

**우리 프로젝트의 위치: 지도 앱이 아니라, 지도 서비스에 들어갈 데이터를 자동으로 만드는 도구.**
우리 지도는 경로 안내용이 아니라 **측정 결과를 위치별로 확인하는 화면**이다.

## 3. 구현 범위

| # | 기능 | 센서 | 방법 | 우선순위 |
|---|---|---|---|---|
| 1 | 단차·턱 측정 | 뎁스 카메라 (+IMU) | PointCloud 바닥 평면 추정 → 높이 급변 경계 → 양쪽 높이 차 | 필수 |
| 2 | 균열 감지 | RGB 카메라 | 공개 균열 모델 적용, 필요 시 보도블럭 사진으로 미세조정 | 선택 |
| 3 | 겉보기 멀쩡한 블럭 감지 | 관절 각도 + IMU (+발 힘) | 발 접지 후 추가 침하·기울어짐이 평소보다 크면 이상 블럭 | 필수 (차별점) |
| 4 | 지도·대시보드 | odom + TF | 1~3 결과를 측정 위치에 표시 | 필수 |

**범위 밖 (향후 확장)**: map 프레임/SLAM, GPS 좌표 변환, 경로 안내, 두 카메라 융합 측정, 서울동행맵 연동.

## 4. 개발 순서: 디자인 먼저, 측정은 나중에

```
[Phase A] 디자인 (지금)          [Phase B] 측정 구현             [Phase C] 교체·평가
예시 데이터 생성                  step / foot / crack 구현         실측 events.csv로 교체
 → events.csv, trajectory.csv     → 같은 형식으로 출력              → 대시보드 그대로 사용
 → 지도·대시보드·신고서 완성                                        → eval로 지표 산출
```

**왜 이 순서인가**
- 출력 형식(`events.csv`)과 화면을 먼저 고정하면, 측정 모듈은 **그 형식만 맞춰서 출력**하면 된다.
- 측정 알고리즘이 늦어져도 지도·대시보드·발표 화면은 미리 완성된다.
- 실측 데이터로 교체할 때 **코드 수정 없이 파일만 바꾸면** 된다.

## 6. 공통 데이터 형식 (모든 단계에서 동일)

### 6.1 `events.csv` — 측정 지점 한 줄씩

| 필드 | 타입 | 예시 | 설명 |
|---|---|---|---|
| `id` | str | `ev_0001` | 이벤트 ID |
| `t` | float | `1792454410.0` | 시간(초, epoch) |
| `session` | str | `20261020_nohyeong_yeon_A` | 측정 세션 이름 |
| `x`, `y` | float | `4.42`, `0.36` | odom 좌표 [m] |
| `lat`, `lon` | float | `33.48606`, `126.48709` | 위도·경도 (`config.yaml` geo로 odom에서 변환, geo 미설정 시 빈칸) |
| `kind` | enum | `step` / `slope` / `crack` / `loose` | 문제 유형 |
| `value` | float | `3.7` | 대표값 (카메라 측정 우선) |
| `unit` | str | `cm` / `deg` / `score` / `mm` | 단위 |
| `source` | enum | `camera` / `foot` / `camera+foot` | 측정 센서 |
| `leg` | str | `FR` | 발 기반일 때 다리 |
| `confidence` | float | `0.85` | 0~1 신뢰도 |
| `level` | enum | `ok` / `warn` / `danger` | 판정 |
| `image` | str | `img/ev_0001.jpg` | 현장 사진 (없으면 빈칸) |
| `note` | str | `횡단보도 진입부 연석` | 비고 |
| `value_foot` | float | `3.9` | 카메라·발 교차 측정 시 발 측정값 |
| `image_mark` | str | `0.5,0.5,0.05` | (선택 열) **흔들림 지점의 발 접촉 위치 표시용** `u,v,r`. u·v: 사진 가로·세로 대비 위치(0~1), r: 짧은 변 대비 반지름(0 초과 1 이하). 흔들림(`loose`)에만 쓰고, 다른 종류는 값이 있어도 표시하지 않는다. 비어 있으면 표시 안 함, `image`가 있을 때만 |

**사진 (`image`, `image_mark`)**
- `image`는 `events.csv` 기준 상대 경로 (예: `photos/step_curb_gap.jpg`). `stepmap map`·`report`가 HTML을 만들 때 원본을 찾아 짧은 변 720px 이하 사본을 `<HTML 폴더>/photos/`에 저장하고 HTML 기준 상대 경로로 연결한다. 원본은 그대로 두고, 사본에는 EXIF(촬영 위치 등)를 넣지 않는다. 원본이 없으면 사진 영역을 만들지 않는다.
- 동그라미는 **겉보기에 멀쩡한 흔들림 사진에만** 그린다. 원본을 수정하지 않고 사진 위에 SVG로 겹쳐 그린다 (`photos.overlay_svg`, 대시보드·신고서 공통): 점선 동그라미(판정 색 + 바깥 흰 테두리) + "발 접촉 위치 (추정) · 다리 이름" (발 위치를 사진에 투영한 추정값, 10.4)
  - 단차·균열은 문제가 사진에 그대로 보이므로 동그라미 없이 사진만 보여 준다
- `image_mark` 열이 없는 이전 파일·기능별 결과도 읽는다 (빈칸으로 채움). 저장할 때는 항상 쓴다.

### 6.2 `trajectory.csv` — 로봇 이동 궤적

| 필드 | 설명 |
|---|---|
| `t` | 시간(초) |
| `x`, `y` | odom 좌표 [m] |
| `lat`, `lon` | 위도·경도 (geo 미설정 시 빈칸) |

**이동 거리**: 직전에 채택한 점에서 1m 이상 떨어진 점만 이어서 더한다 (`events.path_length`). 점마다 있는 cm 단위 위치 흔들림이 누적돼 거리가 늘어나는 것을 막으며, 예시·실측 데이터에 똑같이 적용한다.

**좌표 변환**: 출발점(`geo.origin_lat/lon`)을 odom 원점, `geo.heading_deg`를 odom x축 방위각(북=0, 동=90)으로 두고 평면 근사로 변환한다. odom은 x 전방·y 좌측. 1~2km 범위에서 왕복 오차는 1cm 이내다.

**저장 규칙**: 모든 CSV는 `stepmap/events.py`의 `write_events` / `write_trajectory`로만 저장하며, 저장·읽기 때 형식 검사(열 누락, kind별 단위, enum, 발 측정 시 leg, 교차 측정 시 value_foot)를 거친다. 인코딩은 UTF-8(BOM 포함, 엑셀 호환)이다.

### 6.3 판정 기준 (초기값, 실측 후 조정)

| kind | warn | danger | 근거 |
|---|---|---|---|
| step (단차) | ≥ 1.0cm | ≥ 2.0cm | 서울동행맵 휠체어 회피 기준 2cm |
| slope (경사) | ≥ 4.76° (1/12) | ≥ 7.13° (1/8) | 서울동행맵 기준 1/8 |
| crack (균열) | 점수 ≥ 0.5 | ≥ 0.8 | 모델 출력 |
| loose (흔들림) | 추가 침하 ≥ 3mm | ≥ 6mm | 임시값, 스펀지 블럭 실험으로 확정 |

### 6.4 `foot_traces.csv` — 흔들림 지점의 발끝 높이 기록

흔들림(`loose`) 지점마다 그 걸음의 발끝 높이를 시간에 따라 기록한다. 대시보드 물리적 안정성 페이지의 그래프와 추가 침하 값 상자가 이 파일을 쓴다. 행 하나 = 한 시점.

| 필드 | 타입 | 예시 | 설명 |
|---|---|---|---|
| `id` | str | `ev_0014` | 흔들림 지점 id (`events.csv`와 같음) |
| `leg` | enum | `FL` | 측정 다리 (`FR`/`FL`/`RR`/`RL`) |
| `t` | float | `0.12` | 접지 순간 = 0초. 약 −0.3 ~ +0.8초 |
| `z_step` | float | `-9.89` | 이번 걸음 발끝 높이 [mm] |
| `z_mean`, `z_lo`, `z_hi` | float | `-1.0`, `-2.1`, `0.5` | 같은 다리 평소 걸음의 평균·범위 [mm] (`z_lo ≤ z_mean ≤ z_hi`) |
| `n_normal` | int | `21` | 평소 걸음 수 |
| `t_event` | float | `1792455133.33` | (선택 열) 접지 순간의 절대 시각(epoch 초). 발 분석 모듈 출력은 `id`가 비어 있으므로 `stepmap merge`가 이 시각과 `leg`로 흔들림 지점을 찾아 `id`를 채운다 |

- 높이 기준: **평소 걸음이 딛고 있을 때의 평균 높이 = 0mm**
- 지점마다 `t` 시간순, 같은 `leg`·`n_normal`, 접지 순간(t=0)을 포함해야 한다. 읽기·쓰기·형식 검사는 `events.read_foot_traces` / `write_foot_traces` (`raw=True`: `id` 빈칸 허용, 대신 `t_event` 필요)
- **추가 침하** (`events.extra_sink`) = 이번 걸음이 접지 뒤 내려간 양 − 평소 걸음이 접지 뒤 내려간 양
  - 접지 직후 발이 아직 내려오는 구간은 뺀다: 접지 뒤 발끝 속도가 처음으로 20mm/s 미만이 된 시점(발이 멈춘 시점)부터
  - 내려간 양 = 멈춘 높이 − 다음 발 들기 최고점 전까지의 최저점
  - 접지 높이 차이 = 멈춘 높이 차이 (이번 − 평소), 그래프 값 상자의 "접지 높이: 평소보다 ±N mm"
- 이 값이 `events.csv`의 흔들림 `value`와 같아야 한다 (디자인 데이터는 같게 만든다, 테스트로 확인)
- 파일이 없거나 그 지점 기록이 없으면 대시보드는 그래프 자리에 "발끝 기록 없음"

## 7. Phase A: 예시 데이터 (`stepmap demo`, `stepmap/demo.py`)

현장 상황을 반영해 화면 설계에 필요한 경우를 모두 포함하도록 만든다. 지도 배경을 실제 지도로 쓰기 위해 **제주시 노형동·연동 일대 실제 보도**를 따라 걷는 경로로 만든다.

**궤적** (세션 `20261020_nohyeong_yeon_A`, 약 912m, 3구간)

| 구간 | 보도 | 방향 | 길이 |
|---|---|---|---|
| 1 | 노연로 북측, 연동1길 입구 → 신광로 교차로 | 동 | 약 301m |
| 2 | 신광로 서측, 노연로 → 삼무로 교차로 | 북 | 약 437m |
| 3 | 삼무로 남측, 신광로 → 연동3길 입구 | 서 | 약 174m |

- 두 번 모두 좌회전하고 보도가 항상 진행 방향 왼쪽이라 차도를 건너지 않음 (이면도로 입구만 통과)
- OpenStreetMap 도로 중심선을 보도 쪽으로 평행 이동해 경로 생성 (노연로 북측 차로 5m, 신광로 11m, 삼무로 9m). 오프셋은 중심선에서 건물 벽까지 거리(노연로 6~10m, 신광로 12~18m)보다 작게 잡아 OSM 건물 외곽선 안으로 들어가지 않음 (최소 이격 0.8m). 대시보드 지도에서 확대해 확인
- odom 원점 = 출발점, odom x축 = 첫 구간 방향(방위각 92.9°)
- 0.25m 간격 3,652개 점, 속도 0.45m/s, 위치 흔들림 ±3cm
- 이동 거리 912m (6.2의 1m 거르기 적용, 912.47m를 화면 표시 때 한 번만 반올림. 흔들림을 모두 더하면 926m)

**측정 지점 40개**: 위험 4 · 주의 5 · 정상 31 (위험·주의 약 20%). 실제 보도처럼 대부분 정상이고, 위험은 종류별 1개씩

| 종류 | 개수 | 위험 | 주의 | 정상 | 포함한 경우 |
|---|---|---|---|---|---|
| step | 13 | 1 (4.8cm, 사진) | 2 (교차 측정 1.6cm, 발만 1.0cm = 주의 경계값) | 10 | 카메라+발 교차 측정 7개(값 차이 0.2~0.3cm), 카메라 단독 4개, **카메라 사각으로 발만 잡은 2개** |
| slope | 8 | 1 (7.9°) | 1 (6.2°) | 6 | 2.2~7.9° |
| crack | 11 | 1 (0.91, 사진) | 1 (0.71) | 9 | 점수 0.35~0.91 |
| loose | 8 | 1 (8.5mm, 외관 정상, 사진) | 1 (5.1mm, 외관 정상) | 6 | 추가 침하 1.8~8.5mm, **외관 정상인데 발로 잡힌 경우 4개** |

판정 기준(6.3, `config.yaml`)은 그대로 두고 측정값만 정했다. 비고는 실제 위치에 맞추고 값과 어긋나지 않게 썼다: 위험·주의는 횡단보도 진입부 연석, 주차장 출입구 경사로, 가로수 뿌리 주변 균열 등, 정상은 "보도블럭 이음부", "맨홀 테두리 줄눈"처럼 문제를 단정하지 않는 표현.

**설계 원칙**
- 시드 고정(`20261020`)으로 매번 같은 데이터 생성
- 실측과 **같은 열·같은 단위·같은 판정 기준** 사용 (판정은 `events.judge`, 기준은 `config.yaml`)
- 사진: `stepmap demo --photos data/photos`로 현장 사진 3장을 위험 지점 3곳에 연결 (단차 4.8cm 교차 측정, 균열 0.91, 외관 정상 흔들림 8.5mm). 위치·값·판정은 그대로, `image`·`image_mark`·비고만 채운다. 나머지 지점은 비워 둬 사진이 없어도 화면이 깨지지 않는지 함께 확인

```
stepmap demo -o data/
→ data/trajectory.csv, data/events.csv
```

## 8. 대시보드 설계 (`stepmap map -o dashboard.html`)

입력은 `events.csv`, `trajectory.csv`(+ 있으면 `foot_traces.csv`) 뿐이다. **HTML 파일 하나**로 출력하고(데이터는 JSON으로 파일 안에 포함), 웹 서버 없이 파일을 직접 연다. 왼쪽 사이드바로 4페이지를 오가며, 주소 해시로 페이지와 고른 지점을 기억한다 (뒤로 가기 동작).

| 페이지 | 주소 | 하는 일 |
|---|---|---|
| 종합 현황 | `#home` | 한눈에 보기: KPI 4개, 지도, 위험·주의 지점 목록 |
| 외관 검사 | `#visual/<id>` | 카메라로 본 단차·경사·균열 (발로만 잡은 단차 포함): 목록 + 상세 |
| 물리적 안정성 검사 | `#physical/<id>` | 발 접촉으로 찾은 흔들리는 블럭: 목록 + 발끝 높이 그래프 |
| 점검 이력 | `#history` | 세션별 기록, 필터, 표, CSV 내려받기, 신고서 열기 |

### 8.1 화면 구성

**공통 뼈대**
- 왼쪽 사이드바(248px): 로고, 4페이지 메뉴(고른 메뉴는 왼쪽 강조 막대 + 옅은 강조 배경), 아래쪽에 측정 세션 정보(세션·측정 시간·구간·로봇, 세션 이름이 길면 말줄임 + 마우스를 올리면 전체), 테마 전환 버튼
- 위쪽 제목줄: 한 줄로 얇게 (제목 + 오른쪽에 세션·구간·시각). 스크롤해도 붙어 있고 반투명 + 흐림. 외관 검사·물리적 안정성은 그 위에 경로 표시(`종합 현황 지도 › 단차 4.8cm (ev_0012)`)
- 모바일(760px 이하): 사이드바 → 위쪽 4칸 탭, 목록 → 상세가 위아래로

**① 종합 현황**

```
┌──────────┬──────────────────────────────────────────────────────────────┐
│ StepMap  │ 종합 현황                     세션 · 구간 · 2026-10-20 09:00 │ 제목줄
│          ├──────────────────────────────────────────────────────────────┤
│ ▌종합 현황│ [◎ 점검 거리 912m] [◎ 외관 이상 7 ‼3 !4] [◎ 흔들림 2] [◎ 정상 31]│ KPI (높이 약 90px)
│  외관 검사│ ┌──────────────────────────────────┐ ┌────────────────────┐ │
│  물리적…  │ │ 지도  [밝은 지도|어두운 지도]     │ │ 위험·주의 지점 9건  │ │

└──────────┴──────────────────────────────────────────────────────────────┘
```

- KPI 4개(본문 전체 폭, 같은 너비 4칸, 한 칸이 220px보다 좁아지면 2×2): 아이콘 원 + 라벨 + 큰 숫자, 숫자 오른쪽에 위험·주의 배지나 보조 설명
- 데스크톱(가로 1101px·세로 700px 이상)은 스크롤 없이 한 화면: 지도는 남은 높이, 오른쪽 목록은 지도 상자와 같은 높이로 맞추고 목록 안에서만 스크롤
- 지도: 이동 경로, 양 끝 "출발"(속 빈 원)·"도착"(채운 원), 지점 마커. 마커가 화면에서 16px 안으로 겹칠 때만 묶음 배지(가장 심한 판정 색 + 기호 + 개수)로 묶고, 최대로 확대해도 묶여 있으면 누를 때 부채꼴로 펼친다
- 목록: 위험 먼저, 같은 판정 안에서는 기준 대비 초과 정도(측정값 ÷ 판정 기준값)가 큰 순 (신고서와 같은 순서)

**② 외관 검사**: 왼쪽 목록(탭: 전체·단차·경사·균열, "정상 포함" 선택) + 오른쪽 상세(사진, 큰 값, 기준과 배수, 카메라·발·두 측정 차이 카드, 측정 근거, "지도에서 위치 보기")

**③ 물리적 안정성 검사**: KPI 4개(발로 확인한 지점·흔들림 의심·그중 외관 정상·정상) + 목록 + 상세(사진 위 발 접촉 위치, 발끝 높이 그래프, 추가 침하, 측정 근거, 1m 안 외관 이상 비교). 그래프는 평소 걸음 범위(띠)·평균(점선)·이번 걸음(굵은 선)·위험 기준(점선)과 범례·값 상자 (6.4)

**④ 점검 이력**

```

[점검 거리 912m] [측정 지점 40] [‼ 위험 4] [! 주의 5] [✓ 정상 31]               요약 카드 5개
종류별 판정  ■ 단차  [‼1|  !2  |        ✓10        ]  ‼ 위험 1 · ! 주의 2 · ✓ 정상 10 (계 13)
점검 세션 표  날짜 | 세션 | 구간 | 점검 거리 | 측정 지점 | 위험 | 주의   (세션마다 한 줄)

```

- 필터 4개(세션 / 종류: 단차·경사·균열·흔들림 / 판정: 위험·주의·정상 / 측정 방식: 카메라·발·교차)는 요약 카드·막대·두 표에 함께 적용
- 요약 카드는 종합 현황 KPI와 같은 모양·같은 계산 함수(거리 반올림 한 번, 판정별 개수)
- 지점 표: 기본 정렬은 위험 먼저·기준 대비 큰 순, 열 머리를 누르면 그 열로 정렬(다시 누르면 반대). 행을 누르면 흔들림은 물리적 안정성, 나머지는 외관 검사로 이동. 표가 길면 표 안에서만 스크롤(머리줄 고정), 모바일은 카드형 목록
- **CSV 다운로드**: 현재 필터 결과를 `events.csv`와 같은 열·형식으로 브라우저에서 만든다(서버 없음, BOM 포함 → 엑셀에서 한글 정상). 필터가 없으면 `events.csv`와 바이트까지 같다
- **신고서 열기**: 같은 폴더의 `report.html`을 새 탭으로 연다. `file://`로 연 HTML은 옆 파일이 있는지 확인할 수 없으므로 `map`이 만들 때 확인해 버튼을 넣는다 (없으면 숨김 → `report`를 먼저 실행하거나 `map`을 다시 실행). "인쇄 → PDF로 저장" 안내를 함께 보인다

**클릭 흐름**

```

   ▲                         └─ 단차·경사·균열 ▶ 외관 검사 #visual/<id>
```

### 8.3 자동 신고서 (`stepmap report`)

기존 신고(사진 + 위치 + 유형)에 측정 수치를 붙인 형태. 입력은 `events.csv`, `trajectory.csv`, `config.yaml`.

- `outputs/report.html`: A4 인쇄용 (지점이 쪽 경계에서 잘리지 않음)
- `outputs/report.csv`: 지자체 데이터 제공용. 신고서 목록과 같은 지점·순서·번호, 위도·경도 소수 6자리, 측정 시각 ISO 8601(KST)

**구성**
1. 요약: 세션 이름, 측정 일시, 구간(`config.yaml`의 `report.area`), 이동 거리, 종류별·판정별 건수
2. 위치 확인용 전체 경로 그림 1장: 인터넷 없이 보이는 SVG, 북쪽이 위, 목록 번호 표시
3. 신고 대상 지점: 위험·주의만, 위험 먼저, 같은 판정 안에서는 기준 대비 초과 정도(측정값 ÷ 판정 기준값)가 큰 순

이동 거리(`path_length` → `display_meters`)와 기준 문구(`criterion_text`)는 대시보드와 같은 함수를 쓴다. 데이터 문자열은 HTML 이스케이프, CSV는 수식 주입(`=`, `+`, `-`, `@` 시작)을 막는다.

**현재 노형동·연동 경로 데이터**: 신고 대상 9건 (위험 4 · 주의 5), A4 4쪽 (1쪽 요약·경로 그림, 2~4쪽 지점). 순서는 위험: 단차 4.8cm(2.4배) → 흔들림 8.5mm(1.4배) → 균열 0.91(1.1배) → 경사 7.9°(1.1배), 주의: 흔들림 5.1mm(1.7배) → 단차 1.6cm(1.6배) → 균열 0.71(1.4배) → 경사 6.2°(1.3배) → 단차 1.0cm(1.0배).

**지점 한 건 (1번)**

```

   기준: 휠체어 회피 기준 2cm 이상 (기준의 2.4배)
   측정 방식: 카메라 4.8cm · 발 5.1cm · 앞 오른발(FR) · 차이 0.3cm
   위도·경도: 33.485928, 126.489801
   측정 시각: 09:11:00

   ID: ev_0012

```

## 9. CLI 설계

```
stepmap demo     -o data/ [--split]             # 예시 데이터 생성 (Phase A), --split: 기능별 파일도 data/raw/에

stepmap traj     <bag>  -o trajectory.csv       # odom 궤적 추출
stepmap merge    data/raw/*.csv -o events.csv   # 기능별 결과 합치기 (9.3)
stepmap map      all.csv trajectory.csv -o dashboard.html   # 4. 대시보드
stepmap rviz     all.csv                        # RViz2 MarkerArray 발행
stepmap report   events.csv trajectory.csv      # 자동 신고서 → outputs/report.html, report.csv (8.3)
stepmap eval     all.csv --truth truth.csv      # 지표 계산
```

Phase A에서 구현: `demo`, `map`, `report`, `merge` (예시 데이터만으로 동작)
Phase B에서 구현: `record`, `check`, `step`, `foot`, `traj`, `crack`, `rviz`
Phase C에서 구현: `eval`

### 9.3 병합 규칙 (`stepmap merge`)

**입력**: 기능별 결과 CSV 여러 개 (카메라 단차, 카메라 경사, 카메라 균열, 발 단차·흔들림). 열은 `events.csv`와 같고 `id`·`level`은 비어 있어도 된다. 와일드카드(`data/raw/*.csv`)는 명령이 직접 펼친다 (PowerShell 대응).

**규칙** (거리·시간은 `config.yaml`의 `merge`, 거리는 경계 포함 "이하")

| 대상 | 규칙 |
|---|---|
| 카메라 단차 + 발 단차 | `step_radius_m`(1.0m)·`step_window_s`(10초) 안이면 한 건. 가까운 쌍부터 1:1로 묶는다. `source=camera+foot`, `value`=카메라 값, `value_foot`=발 값, `leg`=발 측정 다리. 위치·시각은 카메라 기준, `confidence`는 둘 중 큰 값, 비고는 중복 없이 이어 붙임 |
| 균열·경사 | 같은 종류가 `dedup_radius_m`(1.0m)·`dedup_window_s`(10초) 안에 여러 번 잡히면 `confidence`가 가장 높은 것 하나만 |
| 흔들림(발) | 카메라 결과와 합치지 않고 그대로 |
| 짝이 없는 카메라·발 단차 | 각각 `camera` / `foot` 단독으로 남긴다 |

시간 창은 같은 장소를 다시 지나갈 때(왕복 경로) 서로 다른 측정을 잘못 합치지 않기 위한 것이다.

**발끝 기록 연결**: 입력에 발끝 기록 파일(`foot_traces.csv` 형식, 머리줄로 구분)이 있으면, 지점 하나의 기록(`t_event` + `leg`)마다 다리가 같고 시각 차이가 0.5초 이하인 흔들림 지점 중 가장 가까운 것에 붙여 `id`를 채우고 출력 폴더에 `foot_traces.csv`로 저장한다 (`events.link_foot_traces`). 한 지점에는 기록 하나만 붙고, 짝이 없는 기록은 경고만 출력하고 저장하지 않는다.

**마무리**: `level`은 `config.yaml` 기준으로 다시 계산하고, `id`는 시간순으로 `ev_0001`부터 다시 매긴다. `lat`/`lon`이 비어 있고 `geo`가 설정돼 있으면 채운다. 출력은 `write_events`로 저장하므로 6장 형식 검사를 통과하며, `stepmap map`이 그대로 읽는다.

**검증**: `stepmap demo --split`은 예시 `events.csv`를 기능별 파일로 나눈다. 교차 측정의 발 쪽은 0.36m·1초 뒤에 밟은 것으로, 균열·경사는 confidence가 낮은 중복 검출을 하나씩 더해 만든다. 이것을 `stepmap merge`로 합치면 원래 `events.csv`와 바이트 단위로 같아야 한다 (`tests/test_merge.py`).

## 10. Phase B: 측정 모듈 상세

### 10.1 단차·경사 (카메라) — `stepmap step`
1. PointCloud를 중력 정렬 좌표로 변환 (TF + IMU, `camera_tilt_offset_deg` 적용)
2. 전방 관심영역(x 0.3~1.5m, |y| < 0.5m) 자르기, 다운샘플링
3. RANSAC 바닥 평면 → 경사 (진행·횡단 성분 분리)
4. 진행 방향 높이 프로파일에서 급변 경계 탐지
5. 경계 앞뒤 평면 각각 추정 → 중력 방향 높이 차 = 단차
6. 정지: 여러 프레임 중앙값 / 보행: 각속도 작은 프레임만

### 10.2 균열 (카메라) — `stepmap crack`
1. 0.3m 이동마다 RGB 프레임 샘플링
2. 사전학습 균열 모델 추론, 필요 시 보도블럭 사진으로 미세조정
3. 뎁스로 균열 위치 → odom 좌표, 사진 저장
4. 줄눈(블럭 이음새)·그림자 오탐률 별도 측정

### 10.3 흔들리는 블럭 (발) — `stepmap foot`
1. `/lowstate` 관절 12개 + IMU + 발 힘
2. 정기구학 → 중력 정렬 (**odom 사용 금지**)
3. 접지 판정: 발 힘(변화 있을 때) 또는 발끝 높이 최저점·속도
4. 걸음별 지표: 다른 접지 발 대비 높이 차(단차), 접지 후 추가 침하(흔들림)
5. 평소 걸음 분포 대비 이상치만 기록, 위치는 접지 시점 odom
6. **출력**: 흔들림은 `events.csv` 형식(`kind=loose`, `value` = 추가 침하 mm)과 함께, 그 걸음의 발끝 높이 기록을 **`foot_traces.csv`(6.4)와 같은 형식**으로 저장한다 (같은 다리 평소 걸음의 평균·범위 포함). `value`는 `events.extra_sink`로 계산한 값과 같아야 한다

검증 실험: 단단한 판 vs 아래 스펀지 깐 판 → `loose_*_mm` 확정

### 10.4 흔들림 발 위치 → 이전 카메라 프레임 투영 (`image`, `image_mark`)

흔들리는 블럭은 외관이 정상이라 사진만으로는 어느 블럭인지 알 수 없다. 발이 밟은 위치를, 발이 그곳에 닿기 전에 카메라가 그 바닥을 찍은 프레임에 투영해 `image_mark`로 표시한다.

1. **발 위치 (관절 + IMU)**: 접지 시점 t₁의 발끝 위치를 정기구학으로 본체 좌표에서 구하고, IMU로 중력 정렬 (10.3과 같음, odom 사용 안 함)
2. **프레임 고르기**: 전방 카메라는 발보다 앞을 보므로, 접지 지점이 시야(전방 0.3~1.5m 관심영역) 안에 들어 있던 이전 프레임 t₀를 고른다 (보행 0.45m/s 기준 약 1~3초 전). 흔들림이 작은(각속도 작은) 프레임 우선
3. **프레임 사이 이동 (odom)**: t₀→t₁ 사이 본체 이동만 odom 차이로 구해, 발 위치를 t₀ 시점 본체 좌표로 옮긴다 (짧은 구간이라 odom 드리프트 영향이 작다)
4. **투영 (TF + camera_info)**: base→camera TF로 카메라 좌표로 바꾸고, `camera_info`의 내부 파라미터(K, 왜곡)로 픽셀 (px, py)를 구한다
5. **표시값**: `u = px / 폭`, `v = py / 높이`, `r` = 블럭 한 장 크기(약 0.2~0.3m)를 그 거리에서 픽셀로 바꾼 값 ÷ 짧은 변. 그 프레임을 `image`로 저장
6. **정확도**: 기구학·IMU·odom·TF 오차가 쌓여 **블럭 한 장 수준**이다. 그래서 화면에는 점선 동그라미와 "(추정)"으로 표시한다. 검증은 바닥에 표식을 둔 시험면에서 투영 위치와 실제 표식의 픽셀 거리로 잰다

## 11. Phase C: 교체와 평가

**교체 절차**
1. `stepmap step/foot/crack/traj` 출력 → `stepmap merge` → `events.csv`
2. `stepmap map events.csv trajectory.csv` → 같은 대시보드
3. 판정 기준을 실측 결과에 맞춰 `config.yaml`에서 조정

**평가 지표 (`stepmap eval`)** — `truth.csv`: 시험면별 줄자·수평계 기준값

| 지표 | 대상 |
|---|---|
| MAE, RMSE | 단차(cm), 경사(도) — 카메라·발 각각 |
| Precision, Recall | 2cm 이상 단차, 균열, 흔들리는 블럭 |
| 정지 vs 보행 오차 | 흔들림 영향 |
| 카메라 vs 발 일치도 | 같은 단차의 두 측정 |
| 반복 재현성 | 같은 시험면 3~5회 표준편차 |

목표(초기): 단차 오차 5mm 이내, 2cm 이상 단차 Recall 0.9 이상

## 12. 실측 데이터 수집 계획 (Phase B)

**시험면**: 평지(S1), 경사 2~3개, 단차 1·2·4cm(D1~D3), 흔들리는 블럭 모형(L1: 판 아래 스펀지), 균열 있는 실제 보도(C1)

| 테이크 | 방법 | 용도 |
|---|---|---|
| 정지 | 0.5 / 1 / 1.5m 앞 10초 | 카메라 기준 성능 |
| 보행 | 천천히 2~3회 | 흔들림 영향, 발 감지 |
| 앞발만 올리고 정지 | 단차에 앞발만 | 발 기반 단차 검증, 다리 순서 확인 |
| 경사면 위 정지 | 정면, 비스듬히 | IMU·네 발·카메라 경사 비교 |

첫 테이크는 항상 평지 정지 10초. 파일명 `시험면_조건_번호`. 테이크마다 `stepmap check`, 철수 전 백업.

| odom 드리프트 | 시험 구간 20~30m, 위치용으로만 |
| 발 계산에 odom 혼입 시 착시 | 관절 + IMU만, 다른 발 대비 상대 높이 |
| 발 힘 해상도 부족 | 발끝 높이·속도로 접지 판정 |
| 균열 오탐 (줄눈·그림자) | 오탐률 측정, 임계값 조정 |
| 녹화 중 메시지 손실 | 토픽 최소화, RGB 해상도·주기 낮추기 |
| 외부 뎁스 카메라 TF 누락 | 줄자 측정값으로 static transform 작성 |

## 15. 발표 메시지

> 서울동행맵 같은 교통약자 지도 서비스는 이미 있지만, 그 데이터는 사람이 조사해 범위가 좁고 갱신이 느리며 수치가 없다. 우리는 로봇개가 보도를 걸으며 **카메라로 단차·균열을 보고, 발로 눌러 겉보기 멀쩡한 흔들리는 블럭까지 찾아내**, 위치·사진·수치가 붙은 데이터를 자동으로 만든다.
