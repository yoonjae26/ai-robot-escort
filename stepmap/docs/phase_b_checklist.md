# Phase B (실측) 준비 목록

Phase A(디자인)에서 고정한 형식·화면을 실측 데이터로 채우기 전에 할 일. 위에서부터 순서대로 진행한다.

- 담당: **개발**(코드·설정·좌표계) / **실험**(현장 측정·기록·사진)
- 계획서: `StepMap_계획서.md`의 절 번호
- 완료하면 `[ ]`를 `[x]`로 바꾸고, 값이 나온 항목은 `config.yaml` 또는 `logs/`에 남긴다.

---

## 1. `config.yaml` 채우기 (계획서 9.1)

로봇·노트북을 연결하고 센서를 모두 켠 상태에서 확인한다. 결과는 `logs/`에 텍스트로 저장한다 (`> logs/topics.txt`).

| | 항목 | 확인 명령 | 담당 | 완료 기준 | 계획서 |
|---|---|---|---|---|---|
| [ ] | 토픽 이름 (`topics.pointcloud`, `depth`, `camera_info`, `rgb`, `odom`) | `ros2 topic list -t > logs/topics.txt`<br>`ros2 topic hz <토픽>` (주기)<br>녹화 파일: `ros2 bag info <bag 폴더>` | 개발 | 5개 토픽 이름이 `<...>` 없이 채워지고, 각 토픽 주기가 `logs/`에 기록됨 | 9.1 |
| [ ] | frame_id (`frames.camera`, `fixed`, `base`) | `ros2 topic echo <토픽> --field header.frame_id --once` (pointcloud·depth·rgb·odom 각각) | 개발 | 카메라 frame_id가 채워지고, odom 메시지의 `header.frame_id`·`child_frame_id`가 `fixed`·`base`와 맞음 | 9.1 |
| [ ] | `camera_info` (내부 파라미터) | `ros2 topic echo <camera_info 토픽> --once > logs/camera_info.txt` | 개발 | `width`·`height`·`k`(초점거리·주점)·`d`(왜곡)가 0이 아님. 사진 투영(10.4)에 사용 | 9.1, 10.4 |
| [ ] | 카메라 TF (base → camera) | `ros2 run tf2_ros tf2_echo base_link <카메라 frame_id>`<br>`ros2 run tf2_tools view_frames` (TF 트리 PDF) | 개발 | TF가 나오면 값 기록. **없으면** 줄자로 잰 장착 위치로 `ros2 run tf2_ros static_transform_publisher --x <> --y <> --z <> --roll <> --pitch <> --yaw <> --frame-id base_link --child-frame-id <카메라 frame_id>` 를 실행 스크립트에 넣음 (계획서 14장) | 9.1, 14 |
| [ ] | `geo` (출발점 위도·경도, 방위각) | 출발 표식 위치를 지도 앱·GPS로 기록, 로봇이 바라보는 방향의 방위각(북=0, 동=90) 측정 | 실험 | `origin_lat`·`origin_lon`·`heading_deg`가 채워지고, 대시보드에서 궤적이 실제 보도 위에 그려짐 | 6.2, 8 |

## 3. 측정 모듈 출력 규칙 (개발)

| | 항목 | 내용 | 담당 | 완료 기준 | 계획서 |
|---|---|---|---|---|---|
| [ ] | **카메라 결과 좌표 = 바닥 위치** | 카메라(단차·경사·균열) 결과의 `x`,`y`는 **로봇 위치가 아니라 단차·균열이 있는 바닥 위치**로 기록한다 (카메라 좌표 → TF → odom). 로봇 위치로 기록하면 0.3~1.5m 앞에 있는 단차가 발 측정 위치와 어긋나 `merge`의 1.0m 규칙(카메라 단차 ↔ 발 단차)이 맞지 않는다 | 개발 | 단차 D2(2cm)를 걸어 지나간 테이크에서 카메라 단차와 발 단차 위치 차이가 0.5m 이내, `stepmap merge` 결과가 `camera+foot` 한 건 | 9.3, 10.1 |
| [ ] | 발 결과 좌표 | 발 결과의 `x`,`y`는 접지 시점의 그 발 위치 (위치 표시용으로만 odom 사용, 높이 계산에는 odom 사용 안 함) | 개발 | 위와 같은 테이크에서 발 단차 위치가 단차 선에서 0.3m 이내 | 10.3 |
| [ ] | 형식 | 모든 모듈은 `events.write_events(..., raw=True)`로 저장 (id·level 빈칸 가능) → `stepmap merge`가 합침 | 개발 | 모듈 출력이 `read_events(raw=True)` 형식 검사 통과 | 6, 9.3 |
| [ ] | **발 분석 모듈이 `foot_traces.csv`를 같은 형식으로 저장** | 흔들림 지점마다 접지 −0.3 ~ +0.8초의 발끝 높이(이번 걸음)와 같은 다리 평소 걸음의 평균·범위·걸음 수를 `events.write_foot_traces`로 저장. 높이 0mm = 평소 걸음이 딛고 있을 때의 평균 높이. 흔들림 `value`는 `events.extra_sink`(발이 멈춘 뒤부터 계산)로 구한다. **`id` 연결**: 모듈 출력 단계에서는 `id`를 비우고 `t_event`(접지 순간 절대 시각 = 흔들림 지점의 `t`)를 채워 `write_foot_traces(..., raw=True)`로 저장한다. `stepmap merge`가 `t_event`·다리로 지점을 찾아 `id`를 채운다 (짝이 없으면 경고) | 개발 | `read_foot_traces(raw=True)` 형식 검사 통과, `stepmap merge`에서 경고 없이 모든 흔들림 지점에 연결, 지점마다 `extra_sink` = `value`, 대시보드 물리적 안정성 페이지에 그래프가 나옴 | 6.4, 9.3, 10.3 |

| | 항목 | 담당 | 완료 기준 | 계획서 |
|---|---|---|---|---|
| [ ] | 단차 높이: 자·수평계로 3번 재서 평균 (cm, 0.1cm 단위) | 실험 | D1~D3 모두 기록 | 11, 12 |
| [ ] | 흔들리는 블럭 위치: 출발 표식 기준 거리(앞 x, 왼쪽 y)를 줄자로, 침하량 | 실험 | L1 블럭 모두 기록 | 11, 12 |
| [ ] | 경사: 수평계·각도계 (°) | 실험 | 경사면 모두 기록 | 11 |
| [ ] | 균열: 위치와 사람 판정(있음/없음, 폭 mm) | 실험 | C1 구간 기록 | 11 |
