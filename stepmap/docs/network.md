# 현장 네트워크: 케이블 없이 로봇 측정 결과 받기

측정 시스템(StepMap live, 카메라·LiDAR 처리)은 **Jetson(192.168.123.18)** 에서 돈다. Go2 앱처럼 노트북을 Go2
WiFi(192.168.12.x)에 붙이면 **Go2 메인보드(192.168.12.1)** 까지만 닿는다. Jetson은 메인보드 뒤 내부망
(192.168.123.x)에 있고, Jetson에는 192.168.12.x로 가는 경로가 없다 (2026-10-26 확인: `ip route`, ping 실패).

그래서 경로를 여러 개 준비하고, 노트북은 닿는 주소를 자동으로 고른다:

```bash
stepmap live -d sessions/<세션> --port 8060 \
  --pull http://192.168.123.18:8060,http://100.65.117.65:8060
#        ① 유선 LAN / ② Go2 WiFi 경유      ③ Tailscale (핫스팟·인터넷)
```
지금 주소가 끊기면 다음 주소를 차례로 시도하고, 마지막으로 받은 순번 다음부터 이어받는다. 대시보드 배지와
`/api/version`의 `pull`에 지금 쓰는 주소가 보인다.

| 경로 | 노트북 | Jetson | 인터넷 | 상태 |
|---|---|---|---|---|
| ① 유선 LAN | 이더넷 192.168.123.222 고정 | 그대로 | 노트북은 WiFi로 | 동작 확인 (개발용) |
| ② Go2 WiFi 경유 (Robot_Go2_Unitree_Hong 방식) | Go2 WiFi + 휴대폰 USB 테더링(인터넷) | 경로 1줄 추가 | 노트북만 | **시험 필요**: 메인보드가 두 망 사이를 전달하는지 |
| ③ 휴대폰 핫스팟 + Tailscale (현장 권장) | 핫스팟 또는 아무 인터넷 | USB WiFi 동글로 핫스팟 접속 (또는 Android USB 테더링) | 둘 다 | Tailscale 이미 설치됨 (로그인 필요) |

## ② Go2 WiFi 경유 시험 (예전 저장소 방식 + Jetson까지)

예전 프로젝트(Robot_Go2_Unitree_Hong)는 노트북을 Go2 WiFi에 붙이고 WebRTC로 **메인보드**와만 통신했다
(그 WiFi에서는 DDS가 안 된다). 측정 시스템은 Jetson에 있으므로 두 망 사이에 경로를 넣어 본다.
메인보드가 패킷을 전달(IP forwarding)하지 않으면 동작하지 않는다. 그 경우 ③을 쓴다.

1. **유선으로 연결된 상태에서** Jetson에 경로 추가 (재부팅하면 사라짐, sudo는 사용자가 직접 입력):
   ```bash
   sudo ip route add 192.168.12.0/24 via 192.168.123.161
   ```
2. 케이블을 빼고 노트북을 Go2 WiFi에 연결, 휴대폰 USB 테더링으로 인터넷 연결.
3. 노트북(관리자 PowerShell)에 경로 추가 (`-p` 없이: 재부팅하면 사라짐):
   ```powershell
   route add 192.168.123.0 mask 255.255.255.0 192.168.12.1
   ```
4. 확인: `ping 192.168.123.18`, 브라우저 `http://192.168.123.18:8060/`, `ssh unitree@192.168.123.18`.
   - 된다 → 경로 ①과 같은 주소로 받으므로 `--pull` 설정을 바꿀 필요 없음.
   - 안 된다 → 메인보드가 전달하지 않음. 경로 제거 (`route delete 192.168.123.0`) 후 ③.

## ③ 휴대폰 핫스팟 + Tailscale (현장 권장)

휴대폰이 네트워크 중심이 되는 점은 예전 방식과 같고, Jetson도 인터넷을 받는다는 점이 다르다.
- Jetson은 WiFi가 없다: USB WiFi 동글(MT7601U / MT76x2U, 드라이버 내장) 또는 Android USB 테더링.
- Jetson이 인터넷에 붙으면 **Tailscale 로그인**(`sudo tailscale up`, 한 번)과 **시계 동기화(NTP)** 가 된다.
  시계가 1970이면 TLS가 실패해 Tailscale 로그인도 안 되므로, 먼저 `sudo date -s "<현재 시각>"`.
- 노트북은 어디서든 `http://100.65.117.65:8060/` (Tailscale)으로 같은 대시보드를 본다.
- 공유기를 쓰면(여행용 라우터를 로봇 등에 고정) 동글 없이 LAN 포트로 연결할 수 있다.

## 시계

인터넷이 없어도 노트북이 `--pull`로 처음 연결될 때 로봇 시계 보정값을 정한다 (docs/live.md). 경로 ②처럼
Jetson이 인터넷에 안 붙는 경우에도 측정 시각은 노트북 기준으로 맞게 기록된다.
